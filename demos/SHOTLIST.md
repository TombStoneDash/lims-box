# LIMS BOX real-product walkthrough shot list

The main recording is the real `https://lims.bot` product. It makes no production writes. The two live intake routes are prospect forms in the current application, not sample-accession forms, so the recording fills every field but intentionally does not press **Send**. Accession, results, QC, and report views are shown through the site's read-only synthetic workflows. The second recording is clearly separated and uses local-only Basic-auth credentials.

## Main file — `demos/out/lims-box-live.webm`

1. **Environmental overview** — Open `/environmental` and slowly scroll from the field-to-bench statement through audit organization and the intake call to action. The viewer sees the environmental product positioning, supported matrices, audit records, and human-review boundary. Narration: “LIMS BOX gives environmental laboratories a local-first documentation layer from field collection through audit preparation.”
2. **Open environmental intake** — Navigate to `/environmental/intake`. The viewer sees every real field supplied by this route: name, email, lab name, lab size, accreditation, field-versus-bench split, documentation pain, and referral source. Narration: “The current environmental intake is a lab discovery form, so this walkthrough uses synthetic contact details and performs no live submission.”
3. **Environmental identity fields** — Type synthetic name `Jordan Rivera`, `jordan.rivera@example.test`, and `Cedar Valley Water Lab (Synthetic)`. The viewer sees slow, visible typing in all three required text fields. Narration: “We begin with a fictional contact and lab identity reserved for demonstration.”
4. **Environmental profile fields** — Select `11–50`, `NELAP`, `ISO 17025`, and `EPA`, then move the field-versus-bench slider to 65 percent field. The viewer sees all actual structured attributes on the page completed. Narration: “Lab size, accreditation framework, and field workload capture the operating context the product must support.”
5. **Environmental narrative fields** — Type a synthetic field chain-of-custody and nitrate/coliform scenario plus `Synthetic product walkthrough` as the referral source. The viewer sees both optional text areas populated and the **Send** control left untouched. Narration: “The discovery record now describes the workflow without creating a prospect or triggering customer-facing activity.”
6. **Environmental sample intake view** — Open `/demo/walkthrough` and click **Sample Intake**. The viewer sees sample `WS-2026-0421`, drinking-water type, Mesa County client, collection date/time, nitrate analysis, collector, preservation, and holding-time countdown. The viewer sees registration, COC creation, electronic collection and receipt signatures, temperature verification, assignment, result entry, and analyst signature. Narration: “The final analytical report presents the signed result, regulatory comparison, holding-time status, and QC outcome in one reviewable view.”

## Local-only file — `demos/out/lims-box-senaite-demo-local.webm`

Start the application with `ADMIN_BASIC_USER=demo ADMIN_BASIC_PASS=demo npm run dev`, then run `node demos/record.mjs local`.

1. **Local demo dashboard** — Authenticate locally and open `http://localhost:3000/senaite-demo`, then scroll through sample status, sample types, dashboard metrics, and action items. The viewer sees a persistent `SYNTHETIC · NON-PRODUCTION` label. Narration: “This second file is a local-only SENAITE-style mockup backed exclusively by fictional demonstration data.”
2. **Local sample/accession detail** — Open `/senaite-demo/samples/SA-2026-0847` and scroll through client, collection, receipt, analysis request, result, flags, and chain-of-custody sections. The viewer sees the only sample route implemented by the application; there is no `/senaite-demo/samples` index route. Narration: “The sample detail follows one synthetic accession from receipt metadata through analytical results and custody events.”
3. **Local QC** — Open `/senaite-demo/qc`, inspect the analyte selector and scroll through each control chart and rule summary. The viewer sees fixed-date synthetic QC evaluation. Narration: “The local QC page visualizes control behavior and rule evaluation without connecting to a production instrument.”
4. **Local equipment** — Open `/senaite-demo/equipment` and scroll through status, calibration schedule, maintenance history, performer, notes, and outcome. The viewer sees instrument readiness and traceable maintenance records. Narration: “Equipment records connect calibration status and maintenance evidence to each fictional instrument.”
5. **Local training** — Open `/senaite-demo/training` and scroll through staff identities, roles, hire dates, electronic-signature status, competencies, certification dates, expiration, status, and assessor. The viewer sees the complete synthetic personnel registry. Narration: “Training records show who is qualified, what competency was assessed, when it expires, and who approved it.”
